# Bind router swaps to published basket versions

## Contract

Both swap directions must validate the mint against the immutable version selected
in the signed transaction. The original BasketConfig composition is not sufficient
after publishing a changed version. Exit transactions must still work while paused.

## Tasks

1. Add a version argument and constrained BasketVersion PDA to both Anchor swap
   instructions. Keep the version account boxed to respect the SBF stack limit.
2. Resolve the stored version ID to its basket and numeric version in backend
   preparation. Reject mismatched baskets/mints. Encode the version and account in
   the transaction before requesting the user's signature.
3. Update validator fixtures and builder regression coverage. Generate the IDL and
   TypeScript interface using Anchor 0.31.1; verify app builds/tests and SBF output.
4. Record local evidence and remaining live acceptance requirements separately.

## Acceptance

- A changed version changes both the PDA and signed message hash.
- Invalid u32 versions are rejected by the builder.
- A mint excluded from the selected published version is rejected before CPI.
- The generated interface has 21 swap accounts and a leading u32 version argument.
- Both app workspaces build and their local tests pass.
- Optimized SBF build succeeds. Live validator execution remains a separate gate.

## Follow-on work and limits

Program close/rebalance preparation is now connected. Each instruction carries
the selected immutable version and an operation fee bounded by the on-chain
global cap: rebalance uses 10 bps per side and close uses the configured close
rate (20 bps by default). Source-version sells and target-version buys are
assembled separately, and the wallet signature remains required.

Still pending is live acceptance: deployed/initialized router state, real pool
accounts, dependent sell→buy simulation against confirmed proceeds, and live
receipt evidence for exact realized fees. Local builders and generated-IDL
interface checks do not claim those devnet outcomes.
